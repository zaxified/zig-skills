## Notes

- Published change since v0.16.0-r2: guidance on the two code generation backends.
  `zig-016-gotchas.md` replaces "Debug builds are for debugging, not for verification"
  with "Two backends: self-hosted for the edit loop, LLVM for test runs" (a measured table,
  which build to use for what, the `use_llvm` build-option pattern), adds "The self-hosted
  x86_64 backend cannot encode what the target CPU lacks" and "Optimize modes are renamed
  after 0.16 (0.17-dev only, not in 0.16.0)". `SKILL.md`: the verification workflow no
  longer says ReleaseFast keeps UB checks (it disables safety checks); the speed tip states
  that self-hosted code runs 2–3x slower.
- Verified on Zig 0.16.0: the new example passes with `-fllvm` and `-fno-llvm` on the
  native CPU and is skipped (compiles) with `-fno-llvm -target x86_64-linux` and
  `-mcpu=baseline`; the same example with only the run-time skip fails there with
  `no encoding found for: none pclmulqdq`, as the text says. `use_llvm` on
  `addTest`/`addExecutable`/`addLibrary`/`addObject`, `-fllvm`/`-fno-llvm` on `zig test`,
  and `builtin.zig_backend` values checked by compiling probes.
- The 0.17-dev rename was read from the master branch's `lib/std/lang.zig` and language
  reference (September 2026) and is labelled as not in 0.16.0.
- Measurements: Zig 0.16.0, x86_64 Linux, eight modules of one library, best of two runs on
  a shared 8-core machine; conditions stated next to the table.
